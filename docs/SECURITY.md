# SECURITY.md — Авто-Отвеччик (веб)

Базовые правила кода и эксплуатации. Дополняет `docs/PLAN.md` (раздел «Риски»).

## Границы доверия

- Клиент видит только своё: магазины, отзывы, подписка. Чужой магазин → 404 (не 403, без утечки существования).
- Админский контур (`/admin`, роли owner/admin/support/content) — только через отдельную сессию и 2FA. Физически не смешивается с клиентской сессией.

## Сессии

- Stateless cookie `aim_session`: `base64url(json{uid, exp}) + "." + base64url(HMAC-SHA256(SESSION_SECRET))`.
- Флаги: `HttpOnly`, `SameSite=Lax`, `Secure` в production, `Path=/`, TTL 14 дней.
- Ротация `SESSION_SECRET` инвалидирует все сессии. Логоут удаляет cookie.
- Пользователь деактивирован (`is_active=false`) → сессия мертва даже с валидной подписью (проверка на каждом запросе).

## Секреты

- WB-токены и AI-ключи клиентов — только Fernet-ciphertext в БД (`wb_token_encrypted`). Открытый текст не в БД, логах, ошибках, экспорте, ответах API.
- `FERNET_KEY` — в env/secret store, не в репозитории. Смена ключа = ресинк секретов (документировать в DEPLOY).
- Magic-link токены хранятся как SHA-256, одноразовые, TTL 15 мин.
- Ответы API возвращают `••••`-маску, никогда — токен (даже замаскированный полностью).
- Логи: allow-list полей; `Authorization`, `api-key`, сырой body с токеном — не логируются.

## Данные

- Тексты отзывов и карточка заказа — минимально необходимый набор; не храним личные контакты покупателя (телефон, адрес) — если WB их отдаёт, отбрасываем на входе.
- Удаление юзера при отмене подписки: каскад `users → shops → reviews`; по запросу — полная выгрузка/удаление (GDPR-подобно, по оферте).

## Публикация (необратимое действие)

- Порядок перед публикацией: локальная проверка уникальности → remote-recheck состояния отзыва в WB → атомарный claim задачи → review-gate (режим/оценка/бюджет) → idempotency marker ДО сетевого вызова.
- Неоднозначный timeout/5xx после POST → НИКОГДА не слепой retry; обязательный recheck через `GET /api/v1/feedback`.

## Админка

- Роли: owner (всё) · admin (users/subscriptions) · support (read-only impersonation, баннер, 403 на мутации) · content (нишевые паки).
- Каждое админское действие пишется в `admin_audit_log` (actor, action, target, diff, ip, ts) — секреты в diff не пишем.
- 2FA (TOTP) обязательна для всех админов; отдельная сессия, короткий TTL.

## Платформа

- prod: HTTPS (Caddy), HSTS; `secure`-cookie; остальные секреты — только env; бэкапы `pg_dump` + ежемесячный restore-прогон; Sentry без тел текстов отзывов (индексируем только типы ошибок).
- Клиент не доверяет фронту: все решения о публикации/биллинге — на бэкенде.
